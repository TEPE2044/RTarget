## 处理情况（2026-09-15）

**根因**：C 的 due_at 继承 A 的，A 一判负 C 就已过期 → 复合体在同一次结算里直接走完
「都没完成」；而「完成其一」分支不关闭 C，C 永远停在 active，compound_a_done 又已写死，
所以两边按钮点了没反应、流程不结束。**机制已按「A/C 各自定死线」修订为 v1.1。**

| # | 反馈 | 处理 |
|---|---|---|
| 1 | 新存档 uuid 一闪而过 | `createArchive` 返回后先把新档推进列表再选中，下拉拿得到选项 |
| 2 | 完成之后按钮还能点 | `completeNode` 加幂等守卫；`canComplete` 先判 `completed_at`，已申报一律不可点 |
| 3 | 左上角时间不动态 | 时钟改为每秒走秒 |
| 4 | 排版 / 分页导航 | 拆成 首页(数据) / 正在执行 / 历史记录 三页 |
| 5 | 封档后要能在历史看到 | 历史页新增封档记录卡：封档时间、免费或扣分、本档净收支、目标数 |
| 6 | 存档进行中下拉红点 | 下拉项带红点 + 图例说明；有 active 节点的存档才亮 |
| 7 | 重大bug 惩罚复合体 | 见上：迁移 0010 重写 settle_all，C 独立死线，结算时把 C 一并收口 |
| 8 | alert 换 toast | 全部 alert 换成 antd `message`，并补上各流程的成功/失败提示 |
| 9 | 复合体独立卡片、左右各一按钮 | NodeList 复合体分支：左栏原目标 A、右栏惩罚 C，各一组按钮，底部写明结算规则 |
| 10 | 文字「认输」→「放弃」 | 前端文案、confirm 提示、代码注释全部改掉 |
