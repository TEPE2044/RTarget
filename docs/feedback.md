## 追加反馈（2026-09-20）

- 惩罚时间应该可以设置为今天，但是不能早于目标设定的时间

### 处理情况（2026-09-20）

**机制修订为 v1.6**：C 的日期从「A 之后 1~3 天」放宽到「**A 当天起 3 天内**」；
选「当天」时时刻必须晚于 A —— 否则 A 一到点 C 就已经过期，复合体开出来就是死的
（就是 0010 修过的那个 bug）。

| # | 反馈 | 处理 |
|---|---|---|
| 1 | C 可以设为今天 | 选项增加「**当天**」（原「后 1/2/3 天」保留），默认仍是后 3 天 |
| 2 | 不能早于目标的时间 | 选「当天」时自动把时刻抬到 A 死线之后（+30 分钟）——**直接改输入框**，不是提交时报错（那时整张表都填完了，被打回来很烦）；选项上和下方都写明实际会用的时刻 |

**两个边界**：

- **A 死线在 23:29 之后**就没有合法的当天时刻了，「当天」按钮直接置灰
- `addGoal` 加了兜底校验：C 不晚于 A 一律拦下（任何路径都不该放过这种组合）

**不需要迁移**：C 的 `due_at` 一直由前端写入，数据库没有相关约束。

## 追加反馈（2026-09-24）

- 在备忘录里写到一半，输入框和按钮全变灰、没法输入，等好久才恢复，然后又灰了

### 处理情况（2026-09-24）

**根因**：奖励 B **无时限**（`due_at` 只是继承 A 做展示），A 完成后 B 变 `active` 等「确认」，
A 的死线一过，它就永远"看起来过期"。而每秒 tick 里的 `autoSettleIfExpired()`（限 30 秒一次）
没排除 B → 每 30 秒命中一次 → 后台 `refresh()` 把全局 `busy` 置真 → 备忘录输入框和按钮
（都绑 `:disabled="busy"`）一起变灰，刷新跑完才恢复，30 秒后又来。

| # | 反馈 | 处理 |
|---|---|---|
| 1 | 输入框 / 按钮反复变灰 | `autoSettleIfExpired()` 排除 B —— 只有带真死线的 A / C 才算过期 |
| 2 | （同上，根子） | 后台自跑的刷新改走 `refresh({ silent: true })`：只更新数据、**不碰 `busy`**。busy 是「用户操作进行中」的锁，后台行为不该禁用界面（正确性靠认领式记账，不靠它） |
| 3 | 顺带 | `NodeList.isOverdue()` 也排除 B：那条奖励原来会挂琥珀色「已超时（待结算）」，跟机制说反了，现在显示绿色「待确认」 |

**验证**：`npm run build`（vue-tsc + vite）通过；7 条边界用例跑过，与旧行为唯一的差异就是 B 那行。
**纯前端改动 → 走 OTA，不需要迁移。**
